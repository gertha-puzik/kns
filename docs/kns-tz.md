> Самодостаточная спецификация для реализации силами ИИ-агентов.
> Документ содержит все факты, нужные для реализации; внешние источники не обязательны.
> Дата: 2026-11-04. Версия формата выверена по живому коду страницы https://catwar.su/cw3/kns
> (клиентский бандл `kns.js`, определение `kns_def.json`).
>
> **Приложение А** (`kns-art-list.md`, рядом с этим файлом) — обязательная часть ТЗ:
> полный перечень арта — все 386 элементов-вариантов с id и русскими именами, все палитры,
> мутации/шрамы, позы. Паре «kns-tz.md + kns-art-list.md» передавать агентам вместе.

## 0. Суть задачи

В игре **coop-field** (общее поле, коты на канвасе, комнаты по WebSocket) сделать **скрытую
страницу `/kns`** — аналог конструктора окрасов CatWar («КНС»). Требования:

1. **Совместимость формата**: страница принимает и выдаёт «код окраса» CatWar — та же грамматика,
   те же 24 слота, те же палитры (раздел 2). Вставил код из CatWar → получил кота с теми же
   цветами основы, глаз, усов и т.д.
2. **Своя модель кота**: рендерится НАША арт-модель (слои-маски), а не спрайты CatWar. У CatWar
   код ссылается на их библиотеку картинок-«элементов» (полоски, пятна) — эти узоры у нас будут
   СВОИ картинки; цвета/смысл/структура сохраняются, внешний вид узоров — свой. Это осознанное
   проектное решение, а не баг.
3. **Две позы**: конструктор рендерит один и тот же код окраса в позах «сидит» и «ходит»
   (в игре коты бегают по полю, статичной позой не обойтись). Поза — свойство сцены, НЕ окраса:
   код и палитры от позы не зависят.
4. MVP — только клиентская страница. Интеграция окраса в игровую комнату — отдельная фаза 2
   (раздел 6), в MVP НЕ реализуется.

Ожидаемый результат: `/kns/index.html` в статической сборке, открывается по прямой ссылке,
с конструктором, превью кота и кодом окраса.

### 2.3 Грамматика кода

```
код      := блок ( " " блок )*           ; ровно 24 блока, порядковый номер = индекс слота
блок     := "0" | слой ( "-" слой )*     ; "0" = пустой слот
слой     := ядро [ "|" p ]               ; p = 0..10
ядро     := цвет | id "/" цвет
цвет     := число (индекс в палитре слота)
p→%      := p*5+50                       ; прозрачность, 0→50%, 10→100%
%→p      := (pct-50)/5
```

Правила (по `Kns.parseCode` / `Kns.code` оригинала):
- Блоки разделяются **одным пробелом**; отсутствие хвостовых блоков у укороченного кода =
  пустые слоты.
- Слои внутри блока пишутся по порядку снизу вверх, через `-`.
- Слой без id (база без варианта, глаза, усы) = просто число цвета. Слой с id = `id/цвет`.
- `|p` пишется только если прозрачность < 100% (p=10 не пишется).
- «Базы»-слоты (0, 15, 16, 17, 18 и др.) реально пишутся с id варианта тела: у CatWar слот 0
  в живых кодах выглядит как `1/18` (id=1 — обычное тело). **Парсер обязан принимать оба вида**
  (`18` и `1/18` для слота 0), экспорт — всегда с id, идентификатор варианта фиксирован = 1.
- Ограничения оригинала: не больше **8 слоёв** на слот (`detailsMax`), не больше **2 слоёв с
  одинаковым id** на слот (`maxSimilarElements`). Валидировать при вводе.

### 2.4 Рабочий пример (реальный код окраса из CatWar)

```
1/18 17|5-16 14/2-8/18-9/2|4-13/14 18/15-8/18-9/2|4-13/14 31/18-41/14|2-19/18 31/12|6-64/1|2-51/12|1-42/2|0-45/17|7-38/2 9/2|9-4/12|7-13/14 2/11|0 2/12|0 9/2|7 1/12-2/12 0 3/2|5 33/17-34/2|5-39/18-15/
```

Разбор начала: `1/18` — основа: тело id 1, цвет 18 (золотистый); `17|5-16` — левый глаз: слой
цвета 17 с прозрачностью p=5 (75%), поверх — слой цвета 16; `14/2-8/18-9/2|4-13/14` — левая
передняя лапа: 4 элемент-слоя с id 14, 8, 9, 13 и цветами 2, 18, 2, 14 (третий — прозрачность
p=4 → 70%)…

Этот пример — обязательный тестовый фикс: вставка кода в конструктор не должна падать,
слоты 0/1/15/16 должны получить цвета 18/17+16/18/18. Слои, для которых ещё нет нашей
картинки (см. Приложение А), — пропущены с примечанием «пропущено N (нет картинки)»;
при полном арт-паке пропусков ноль. «Неизвестных id» не бывает: все id перечислены
в Приложении А.

## 3. Контракт арт-модели (наша модель кота)

Модель — набор **масок по слотам × позы** + палитры из раздела 2.2. Формат файлов — PNG или SVG.

- **Позы**: каталог на позу — `sit` (сидит) и `walk` (ходит); в будущем позы добавляются
  (`run`, `lie` и т.п. — у CatWar та же идея: сегмент `{act}` в их путях к спрайтам).
- **common-слои**: слоты, не меняющиеся между позами (глаза 1/19, нос 23, усы 22, элемент
  морды 5, уши 7/8, грива 16 — при условии, что голова в обеих позах в одном месте холста),
  живут один раз и подставляются во все позы. Остальные слоты (основа 0, лапы 2/3/13/14,
  элемент туловища 4, хвост 15, элементы 9–12/20/21) — свои в каждой позе.
- **Кадры ходьбы**: в позе `walk` анимируемые слоты имеют файлы `*_f1`, `*_f2`, … (минимум
  2 кадра — смена положения лап,optional лёгкий bob корпуса); частота ~150 мс/кадр. В `sit`
  кадры не нужны.
- Общий холст для всех файлов: **240×170** px (viewBox/размер картинки), позиция кота на холсте
  фиксирована и одинакова во всех файлах. Слои выравниваются по холсту, а не друг по другу.
  Позы кладутся на ОДИН И ТОТ ЖЕ холст (голова/грива в одном месте), чтобы common-слои не
  «ехали» между позами.
- Маска-слот = только **альфа**: там, где кот закрашен — заливка `#7f7f7f` (или белая), остальное
  — прозрачное. Тонирование: цвет = прямоугольник сплошной палитры → `globalCompositeOperation
  = "source-in"` → поверх маска; результат рисуется на общий канвас в z-порядке.
  У CatWar глаза/усы — НЕ маски, а готовые цветные спрайты (palette cut=false). Упрощение MVP:
  **всё красим как маски**, для глаз допустимо добавить в файл чёрный зрачок вторым path'ом
  (зрачок не тонируется).
- `shading` — необязательный слой-оверлей поверх всех тонированных слоёв: те же 240×170,
  полупрозрачные белые/чёрные формы (тут градации СЕРОГО важны). Рисуется последним через
  `"source-over"` или `"multiply"` — даёт объём.
- Элемент-«штампы» (все слоты-элементы: 2–14, 20, 21): картинка-элемент имеет **id внутри
  слота**, и эти id ОБЯЗАНЫ совпадать с оригиналом — иначе код CatWar показывает не то.
  **Полный перечень id и имён — Приложение А** (`kns-art-list.md`): 386 элементов по 24 слотам
  (полоски, пятна, мраморы, ремни, носки/чулки/пальцы, затушёвки и т.д.).
  Правила переноса:
  - (а) элементный РЕЕСТР страницы знает ВСЕ id из Приложения А с русскими именами (все
    видны в UI выбора элемента — как в оригинале);
  - (б) нарисованных картинок может не хватать — слой с ненарисованным элементом
    пропускается с пометкой «не нарисовано: N слоёв» (graceful, не ошибка);
  - (в) арт доводится до полного покрытия ДОБАВЛЕНИЕМ ФАЙЛОВ по конвенции имён —
    без правок логики/код-грамматики;
  - (г) уникальные окрасы (id 2 основы, палитра 2) и характеристики/мутации из
    Приложения А — этап 2; в MVP обязательно graceful-skip их слоёв.
- Naming: `public/kns-art/{pose}/slots/{NN}_{name}[_fN].svg` (+ `*_e{elementId}[_fN].svg` для
  элементов), common-слои — `public/kns-art/common/slots/…`, шейдинг — `{pose}/shading.svg`
  (объём у разных поз свой). Разрешение светлый/тёмный скин не требуется.

Референс-модель (готовая, можно взять за основу): в workspace `research/kns-clone/artpack/`
— SVG-маски слотов 0,1,2,3,4,5,7,8,15,16,22,23 в ОБОИХ позах (sit/walk, ходьба — 2 кадра)
+ шейдинг на позу + рабочее демо `kns-preview.html` (проверено: вставка реального кода
CatWar рендерится в обеих позах, roundtrip идемпотентен, смена позы код не меняет).
Если доступа в workspace нет — выражай ту же структуру с нуля, контракт выше полон.

## 4. Требования к странице `/kns` (MVP)

### 4.1 Обязательные функции

1. **Превью**: канвас (масштаб 2x от 240×170), слой-композиция по разделу 2.5; переключатель
   позы «Сидит / Ходит» — рендерит тот же окрас в другой позе; код и состояние слотов при
   смене позы НЕ меняются. В позе «Ходит» при наличии кадров — циклическая анимация
   (~150 мс/кадр).
2. **UI-группы слотов** как у CatWar: «Основа», «Шея и морда», «Туловище», «Лапы и хвост».
   Для каждого слота: текущий цвет, миниатюра, выпадающие/инлайн-сванчи его палитры.
3. **Слои**: в слот-элементе — кнопка «+ Элемент» (добавляет следующий доступный id; лимит 8
   на слот), удаление слоя, стрелки ↑/↓ порядка слоёв, ползунок прозрачности 50–100% с шагом
   5% (→ код `|0..|10`, пишется в живой код немедленно). Грид выбора элемента — как у
   оригинала: переключатель «иконки / имена» (аналог `Kns.detailVariant`: 1 = иконки-плитки,
   0 = текстовый список имён); иконки — из нашего арт-пака (SVG), отсутствующие — подпись
   с русским именем (не пустышка и не 404).
4. **Прозрачность** учитывается в рендере (globalAlpha).
5. **Код окраса**: поле «ваш код» (readonly, кнопка копирования) + поле вставки чужого кода c
   кнопкой «Применить». Парсинг — строго по грамматике 2.3, невалидные id — skip + счётчик.
   Экспорт — 24 блока, всегда id=1 для баз.
6. **Кнопки**: «Случайный окрас» (случайные валидные цвета по палитрам), «Сбросить» (дефолт:
   основа id золотистый, глаза зелёные, усы светлые; что-то симпатичное).
7. **Сохранение состояния** в localStorage (`coop_kns_current`), восстановление при открытии.
8. Мета `noindex`; страница на русском; не ломает сборку и остальные страницы.
9. Работает оффлайн-статикой: внешних запросов нет (никаких CDN шрифтов/скриптов; палитры
   и грамматика — зашиты локально; НЕ дергать catwar.su в рантайме).

### 4.2 Не-цели (НЕ делать в MVP)

- Не трогать контракт игровой комнаты (`server.js`, WebSocket-протокол, `drawChar`).
- Не копировать в репозиторий ассеты CatWar (ни спрайты, ни `kns_def.json` — палитры уже
  перечислены в этом ТЗ текстом; commit их данных запрещён).
- Без авторизации, без бекенда, без базы: страница целиком клиентская.
- Мутации/шрамы/купоны CatWar (альбинизм, витилиго...) — вне MVP; допускается задел:
  отдельное поле в состоянии, пока не отображается.

## 5. Чек-лист приёмки (критически для «судейства» битвы реализаций)

Реализация засчитывается, если выполнено ВСЁ:

1. `npm run build` проходит; `out/kns/index.html` существует и открывается.
2. Открытие страницы не даёт ошибок в консоли.
3. Код тестового фикса (2.4) вставляется без ошибок: слот 0 = золотистый `#e5bd7f`,
   глаза — цвет 17 (рыжий `#ed9b2d`) поверх цвета 16, хвост = цвет 18; рендер не пустой.
   Счётчик пропущенного считает слои БЕЗ картинки из Приложения А (при полном арт-паке — 0);
   «неизвестных id» быть не должно — все id известны из Приложения А.
4. Свои изменения → экспорт кода → очистка → вставка своего кода = идентичная картина
   (roundtrip идемпотентен).
5. Прозрачность: ползунок 75% имеет в коде `|5` и обратно, код `|0` = 50% в рендере.
